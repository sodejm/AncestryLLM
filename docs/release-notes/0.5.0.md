# AncestryLLM 0.5.0

AncestryLLM 0.5.0 introduces the supported offline Electron desktop shell on
macOS, Windows, and Ubuntu, distributed as manual full installers alongside the
existing one-shot CLI and prompt-toolkit/Rich REPL surfaces.

## Highlights

- A three-OS Electron shell with Home, Diagnostics, Settings, and
  capability-onboarding screens, served by a private loopback FastAPI sidecar.
- Verified manual full-installer packages for macOS 15 arm64, macOS 15 x64,
  Windows 11 ARM64, and Ubuntu 24.04 x64. The arm64 and x64 DMGs cover the
  supported macOS 15/26 range without a separate macOS 26 installer.
- Authenticated FastAPI health and capability foundation for the sidecar,
  consumed by the Electron host through a private local port with token
  verification before any parsing.
- Desktop verification sidecar with immutable API-contract, IPC-sender
  validation, domain-routes-absent, provider-none-network-free, and
  redaction gates.
- Pre-1.0 binary-signing disclosure embedded in release notes and the release
  workflow for every 0.x official desktop publication.

## Supported installer matrix

| Platform | Architecture | Installer |
|---|---|---|
| macOS 15 | arm64 | DMG (also validated on macOS 26 arm64) |
| macOS 15 | x64 | DMG (also validated on macOS 26 x64) |
| Windows 11 | arm64 | NSIS executable |
| Ubuntu 24.04 | x64 | DEB package |

## Offline scope

v0.5.0 desktop scope is Home, Diagnostics, Settings, and capability
onboarding. It excludes genealogy jobs, chat providers, cloud accounts,
updater behavior, and background release channels.

## Manual full-installer update model

v0.5.0 has no updater feed, no background update, no staged rollout, and no
blockmap. Every update requires manually downloading and running the new
full installer. The previous installation is not automatically removed.

## Preserved compatibility and safety

The one-shot CLI and prompt-toolkit/Rich REPL remain the only implemented
CLI adapters. Command grammar, stable coded errors, immutable RootsMagic
inputs, loss-minimal GEDCOM handling, explicit provider selection and consent,
and network-free `provider=none` behavior are unchanged.

Provider `none` remains network-free even when environment keys exist.

## Verified release guarantees

Publication is gated on the attached `release-evidence.md`. A `verified` gate
means the exact release commit passed the documented tests, static analysis,
security checks, reproducibility checks, clean-install matrix, and hosted
control checks. The wheel and source distribution must have the same hashes as
the approved readiness build before publication proceeds.

The release workflow verifies installation on Ubuntu, macOS, and Windows with
Python 3.12, 3.13, and 3.14. TestPyPI and PyPI publication use Trusted
Publishing; the workflow requires identical distribution hashes at both
indexes and attaches PEP 740 attestations and GitHub build provenance.

Desktop publication imports the exact immutable desktop aggregate produced and
validated by the pre-tag workflow run without rebuilding, repackaging,
re-signing, or modifying any desktop member.

## Binary signing

This pre-1.0 release is intentionally unsigned. Project-produced release
installers and the annotated release tag must not be signed, and operating
systems may show an unknown-publisher warning. Full trusted platform signing
and signed annotated release tags start with v1.0.0.

Binary-signing mode for this release: `unsigned`.

Release-tag mode for this release: `unsigned-annotated`.

### Known warnings

- **macOS**: Gatekeeper will show an "unverified developer" warning when
  opening the DMG or the installed application. Right-click → Open, or allow
  the application in System Settings → Privacy & Security, to proceed.
- **Windows**: SmartScreen will show an "unknown publisher" warning. Click
  "More info" then "Run anyway" to proceed.
- **Ubuntu**: No additional warning; the DEB can be installed with `sudo dpkg`.

## Interoperability limitations

RootsMagic, Ancestry, Geni, and MyHeritage interoperability is `unverified` for
0.5.0 because no dated fictional-data manual import evidence is recorded. This
release does not make a positive compatibility claim for an unverified vendor.
Automated tests verify standards-based GEDCOM formatting, deterministic
loss-minimal preservation, and immutable RootsMagic handling only.

## Installation

Install the isolated CLI application with:

```bash
pipx install ancestryllm==0.5.0
```

Then verify the installed public version:

```bash
ancestry --version
python -m ancestryllm --version
```

Both commands return `ancestry 0.5.0`.

For the desktop application, download the installer for your platform from the
GitHub Release and follow the platform-specific instructions above.

## Release assets and verification

The immutable GitHub Release contains the macOS arm64/x64 DMGs, Windows 11 ARM64
NSIS executable, Ubuntu 24.04 x64 DEB, wheel, source distribution, full
`SHA256SUMS`, CycloneDX SBOMs, binary-signing disclosure, artifact manifest,
exact-head evidence, security-finding dispositions, interoperability record,
readiness evidence, final release evidence, and provenance attestations.

GitHub build provenance binds the assets to the release workflow and commit.
PyPI Trusted Publishing attestations bind the Python distributions to the same
release workflow.

Verify all downloaded GitHub assets from the directory containing them:

```bash
shasum -a 256 -c SHA256SUMS
```

`SHA256SUMS` intentionally omits only itself.

## Upgrade and correction policy

Published artifacts and `v0.5.0` are immutable. If a defect requires a
correction, the project will publish a new patch version rather than replacing
this tag or version. Earlier tags, releases, notes, and evidence remain
unchanged.
