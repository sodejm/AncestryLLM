## Acceptance criteria and evidence

### #504: reject duplicate synchronization identifiers

Acceptance criteria:

- Validate the master and every snapshot before idempotence checks or
  reconciliation. Reject duplicate identifiers within a document with
  `SYNC_PARSE` before publication.
- Preserve source bytes, master bytes, manifest, and generation on rejection.
  A corrected retry retains the expected generation behavior.
- Allow the same identifier in distinct documents where the existing sync
  contract permits it.

`tests/modular/test_sync_duplicate_identifiers.py` covers all five cases.
The first focused run exposed two expected failures; all five passed after
the fix. Adjacent incremental-sync and service regressions passed, and the
combined canonical Python suite passed at the implementation commit.

The [CLI reference](../reference/CLI.md) documents the failure and recovery
contract. This strengthens existing structural validation and publication
boundaries without adding a transport or trust boundary; architecture and
threat-model changes are therefore unnecessary for this item.

### #505: bound merge identifier allocation

Acceptance criteria:

- Allocate deterministic, unique, resolving identifiers using a per-namespace
  cursor, without restarting a dense suffix search for every collision.
- For 128 occupied suffixes in the fixture, allocate `I2_129` consistently.
- Observe cancellation within 65 allocation probes and abort before
  publication.

The focused tests first exposed the missing allocator behavior and then the
129-probe cancellation delay. The allocator, adversarial, and merge checks
passed after repair. `tests/test_gedcom_pointer_allocator.py` exercises six
cases through the public parser contract; the combined suite passed.

`src/ancestryllm/gedcom/MERGE_IDENTIFIER_ALLOCATION.md` documents allocation,
complexity, and cancellation. This changes an internal algorithm while
preserving the existing merge API and trust boundaries; architecture and
threat-model surfaces are unaffected.

### #489: isolate and bound GEDCOM inspection

Acceptance criteria:

- Execute inspection in a separate child with fixed provider `none`, a minimal
  environment, explicit ingress, parser, deadline, memory, output, and
  concurrency budgets, and bounded public output.
- Handle crashes, cancellation, timeout, and forced termination by reaping the
  child and cleaning private staging. Preserve the original source.
- Admit only reviewed private output files and dispatch the worker correctly
  from both source execution and the frozen native executable.

`tests/test_gedcom_inspection_worker.py` covers exact and over-budget inputs,
crashes, RSS and deadline enforcement, forced termination, custom ingress
limits, and real child execution. `tests/test_sidecar_entry.py` covers native
worker dispatch and invalid arguments. Frozen-dispatch regressions first
failed in three focused cases; all 35 focused cases passed after repair. The
canonical suite and an actual built macOS arm64 worker smoke test passed.

Key budgets are 512 MiB source bytes, 250,000 individuals, one shared 120-second
queue/preflight/execution deadline, 1 GiB RSS, two concurrent workers, 256 MiB
index bytes, and 1 MiB summary bytes. Linux also applies `RLIMIT_AS`.
Provider `none` is network-free application behavior; this is not an OS-level
network sandbox claim.

`INSPECTION_WORKER.md`, the [sidecar reference](../reference/DESKTOP_SIDECAR.md),
`ARCHITECTURE.md`, and the [threat model](../THREAT_MODEL.md)
document isolation, private custody, lifecycle, and native dispatch.

### #490: retain a private, expiring root index

Acceptance criteria:

- Stream minimal root candidates into an atomic private SQLite index, with
  POSIX 0700 directories and 0600 files or verified Windows owner/DACL privacy,
  a 256 MiB cap, and no public candidate vector.
- Use indexed exact identifier lookup with known totals and no fuzzy fallback
  for an exact person reference. Bound fuzzy scans to 4,096 candidates and
  pages to 100, including valid empty continuation pages.
- Bind opaque leases and authenticated cursors to job, source, query, and
  offset; retain at most eight successful leases for 15 minutes.
- Revoke and erase results on expiry, disposal, cancellation, eviction,
  discarded late completion, and shutdown. Reject stale or mismatched results
  with a coded error.
- Avoid repeated full-index integrity scans on unchanged exact lookups while
  revalidating file replacement, metadata changes, and permission changes.

`tests/test_gedcom_root_index.py`, `tests/test_gedcom_inspection_leases.py`,
`tests/test_job_result_cleanup.py`, and modular job-facade regressions cover
these contracts. Cleanup initially failed in six cases before implementation.
The 10,000-record exact-lookup regression first measured 170,400 SQLite VM
steps; the repaired unchanged lookup stayed below 5,000. Corrupt replacement
and changed permissions remain covered. All relevant tests and the canonical
suite passed.

`src/ancestryllm/gedcom/ROOT_INDEX.md`,
`src/ancestryllm/gedcom/INSPECTION_RESULTS.md`,
`src/ancestryllm/core/CORE_JOBS.md`, and the
[API reference](../reference/api/API_REFERENCE.md)
document lookup and ownership contracts. Architecture and threat-model
documentation were updated for disk custody, expiry, bounded public results,
and worker/service responsibilities.

### #491: make asynchronous desktop intake explicit

Acceptance criteria:

- Expose queued, running, cancelling, and safe-point states through visible
  controls, `aria-busy`, and polite screen-reader announcements.
- Support named candidate lists, native radio-button keyboard selection, and
  wrapping long labels.
- Prevent removed sources from returning after late completion, unmount,

  and results through the existing Main-process boundary.

`desktop/src/renderer/src/GedcomIntakeWorkspace.test.tsx` first reported three

responsiveness, and packaged workflow acceptance remain unverified.

The [intake guide](../how-to/desktop-gedcom-intake.md) and

The renderer reuses existing service, job, and Main-process authority
contracts; it introduces no additional command registry or trust boundary.
